# DECISIONS

## 1. Stream без побочных эффектов; исходный список не изменяется
Все методы `SalesAnalyticsService` строят результат цепочкой `filter/sorted/limit/collect` (или `groupingBy`,
`max`, `average`) и возвращают НОВУЮ коллекцию. Накопление в внешний `ArrayList` через `forEach(result::add)`
не используется: результат собирает `collect`. `maxSale` возвращает `Optional`, а не `null`.
Один и тот же расчёт (`largeTotal`) оставлен в двух вариантах — императивном и stream — для сравнения.
Stream использован там, где цепочка читается как описание задачи; простые циклы не переписывались ради моды.

## 2. Comparator с двумя полями — в одном месте (вариант 5)
`SaleComparators.AMOUNT_DESC_THEN_REGION`: сумма по убыванию, затем регион по алфавиту (вторичное поле варианта 5).
Смена вторичного поля — изменение одной строки `thenComparing(...)`. Порог «крупной сделки» и параметр 30
(`DEFAULT_TOP_LIMIT`, число записей `topSales` по умолчанию) — в `SalesRules`, а не по коду сервиса.

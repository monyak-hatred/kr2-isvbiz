# DECISIONS

## 1. Два уровня ошибок: файл завершает импорт, строка — нет
Ошибки файла (нет файла, нет доступа, пустой файл, битая кодировка) — проверяемое `ImportException`
(наследник `IOException`), оно выходит из `importFile` и останавливает операцию. Ошибка одной строки — это
`RowFormatException` (парсер) или `ValidationResult.fail` (валидатор); они ловятся ВНУТРИ цикла, записываются
в `ImportResult` с номером строки и причиной, и цикл переходит к следующей строке. Общего `catch` вокруг
всего цикла нет. Чтение — `Files.newBufferedReader` в try-with-resources: файл читается построчно, ошибка
чтения (в т.ч. некорректный UTF-8) всплывает там, где произошла.

## 2. Разделение ответственности и правило варианта 5
`ClientCsvParser` только режет строку (`split(";", -1)`, чтобы не терять пустые хвостовые поля),
`ClientValidator` только проверяет (ИНН 10/12 цифр, email, имя), `ClientRepository` только хранит,
`ClientImporter` только координирует. Вариант 5 — дополнительная проверка строки «имя не длиннее 30 символов»:
значение `ImportRules.MAX_NAME_LENGTH`, проверка в одном месте — `ClientValidator`. Дубликат ИНН:
побеждает первая принятая запись, повторная отклоняется с номером первой строки; невалидная строка ИНН не занимает.

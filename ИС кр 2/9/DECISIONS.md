# DECISIONS

## 1. Map для позиций, List только для журнала
Позиции хранятся в `LinkedHashMap<String, StockItem>` по инвентарному коду: уникальность проверяется
`containsKey`, поиск — `get`, без перебора. `List` хуже, потому что пришлось бы линейно искать код и отдельно
следить за дубликатами (ровно тот цикл из «плохого фрагмента»). `List` оставлен для журнала `movements`:
там важен порядок во времени и допустимы повторы. Для уникальных перечней категорий и кодов используются
`EnumSet` и `TreeSet`. Наружу отдаются только копии коллекций.

## 2. Лимит дополнительной категории хранится в самом enum
Вариант 5 — дополнительная категория `NETWORK` с лимитом остатка 30. Лимит — поле `Category.maxStock`
(у остальных категорий без ограничения), проверка — в одном месте, `StockItem.increase`. Добавление
или изменение категории не затрагивает `Warehouse`. Все проверки выполняются до изменения остатка.
